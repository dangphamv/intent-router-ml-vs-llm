1. Cách chạy

Cài đặt (một lần)

git clone https://github.com/dangphamv/intent-router-ml-vs-llm
cd intent-router-ml-vs-llm
brew install libomp        # macOS: XGBoost cần thư viện này
uv sync                    # cài thư viện Python 3.12 vào .venv

Cách 1 — Xem kết quả, không cần API key

uv run jupyter lab notebooks/intent_router.ipynb   # Run All

Notebook đọc kết quả gọi API đã lưu trong data/cache/ và train lại model A, B, C ngay trên máy (khoảng 1–2 phút).

Cách 2 — Chạy lại toàn bộ pipeline (cần key)

cp .env.example .env                    # điền OPENAI_API_KEY=sk-...
uv run scripts/build_dataset.py         # bước 1: tạo dữ liệu          (~5 phút lần đầu)
uv run scripts/run_experiments.py       # bước 2: so sánh A–D + hybrid (~4–5 phút)
uv run scripts/rare_class_ablation.py   # bước 3: thí nghiệm lớp hiếm  (vài phút, không gọi API)
uv run scripts/route.py "Gói Pro bao nhiêu tiền?" "app lỗi 500"   # thử router

Mọi lần gọi API đều được lưu cache, nên chạy lại lần sau gần như miễn phí và cho cùng kết quả.

Dùng router trong code (dự án #3)

from intent_router.router import IntentRouter

router = IntentRouter.load()     # TF-IDF + LR (fit trên train+val), ngưỡng 0,72 → gpt-4o-mini
route = await router.route("app bị lỗi 500 khi lưu task")
route.label, route.confidence, route.handled_by   # ("tech_support", 0.97, "local")

3.1 Dữ liệu · 25%

ĐạtKhoảng 2.000 tin có nhãn: tự gán ~300, phần còn lại LLM gán rồi kiểm tra mẫu
BướcCách làmCông cụ & thông số

300 tin seedViết tay đủ kiểu: có dấu, không dấu, teencode, Vietglish, ca khópricing 70 · complaint 65 · cancellation 35 · tech_support 75 · other 55
Sinh 1.700 tinLLM viết tin theo từng nhãn; mỗi lần gọi có 4 văn phong, 1 persona, 6 ví dụ seed; ~20% là ca khógpt-4o-mini, temperature 1.0, 20 tin/lần, sinh dư ×1.2 rồi lọc trùng; 10 văn phong, 11 persona. Mục tiêu 380 / 355 / 145 / 445 / 375
Lọc trùngSo sánh sau khi bỏ dấu, chuyển chữ thường, bỏ ký tự đặc biệthàm normalize()
Gán nhãn bằng LLMModel khác và mạnh hơn gán nhãn độc lập theo guidelinegpt-4o, temperature 0, structured output (Pydantic), 25 tin/lần gọi (giới hạn 30k token/phút)
Xuất sắcKiểm tra chất lượng nhãn LLM bằng người (đồng thuận ≥ 90%)
  • Trên 300 tin seed: annotator khớp người 99,0%, Cohen's κ = 0,987 (κ là độ đồng thuận đã trừ phần trùng do ngẫu nhiên).
  • Kiểm tra mẫu 100 tin LLM gán, lấy ngẫu nhiên (seed 42): khớp 95%. 5 nhãn bị sửa được ghi đè vào dataset.
  • Công cụ: sklearn.metrics.accuracy_score, cohen_kappa_score.
ĐạtChia train / val / test 70 / 15 / 15, giữ nguyên tỷ lệ lớp
  • Chia 2 lần bằng train_test_split(stratify=label, random_state=42): tách 70/30, rồi chia đôi phần 30.
  • Kết quả 1.400 / 300 / 300; tỷ lệ từng lớp giữa 3 tập lệch nhau dưới 0,5 điểm %.
  • Đã kiểm tra rò rỉ: không tin test nào giống tin train quá 0,9 (cosine embedding).
Xuất sắcXử lý lớp hiếm (cancellation ~10%)
  • Chia stratified để tập nào cũng đủ tin cancellation.
  • A, B: class_weight="balanced"; C: compute_sample_weight("balanced"). Báo cáo F1 riêng từng lớp.
  • Thí nghiệm kiểm chứng: CV 5-fold, có / không weight, ở tỷ lệ tự nhiên và khi ép lớp hiếm còn ~2,9% (chỉ giữ 25% tin hủy trong phần train của fold).
CáchTỷ lệ cancellationRecall: không → có weightF1 lớp hiếm: không → có weight
A. TF-IDF + LR10,5%0,84 → 0,880,90 → 0,91
A. TF-IDF + LR2,9%0,57 → 0,720,73 → 0,83
B. Embedding + LR10,5%0,89 → 0,900,93 → 0,91
B. Embedding + LR2,9%0,64 → 0,840,77 → 0,90
C. Embedding + XGBoost2,9%0,47 → 0,540,63 → 0,70

Ở ~10%, weight gần như không đổi gì. Khi lớp hiếm còn ~3%, không có weight thì model bỏ sót gần nửa số khách muốn hủy; có weight thì recall tăng mạnh mà precision vẫn ≥ 0,97.

3.3 Chiến lược kết hợp · 25%

ĐạtModel rẻ xử lý khi tự tin (xác suất > 0,8), còn lại chuyển LLM; báo cáo tỷ lệ chuyển và chất lượng tổng 
nếu max(predict_proba) > ngưỡng → dùng nhãn của model rẻ   # local, ~0,6 ms, $0
ngược lại                       → gọi gpt-4o-mini          # ~750 ms, $3,23 / 100k

Code ở experiments.hybrid_curve(). Ở ngưỡng 0,8: A → D chuyển 32,7% sang LLM, macro-F1 0,940; B → D chuyển 26%, macro-F1 0,945.

Xuất sắcVẽ đường đánh đổi chi phí – chất lượng theo ngưỡng, chọn ngưỡng có lý do
  • Quét ngưỡng 0 → 1, bước 0,01; mỗi ngưỡng tính macro-F1, % chuyển LLM, $/100k, p50, p95.
  • Không dùng test để chọn ngưỡng: dùng xác suất out-of-fold của CV trên train+val (1.700 tin). Không dùng val 300 tin vì quá nhiễu — lần đầu chọn trên val cho 0,94, nhưng test chỉ còn 0,91.
  • Quy tắc: ngưỡng rẻ nhất mà macro-F1 không thấp hơn LLM-only trên cùng dữ liệu — giữ chất lượng LLM với chi phí thấp nhất (pick_threshold()).

Cấu hình

Đổi model qua biến trong .env: LLM_MODEL (mặc định gpt-4o-mini), LABEL_MODEL (gpt-4o), EMBED_MODEL (text-embedding-3-small). Dùng model mới thì thêm giá vào PRICES trong src/intent_router/config.py.

Giới hạn

300 tin seed và 100 tin audit được soạn / review cùng Claude Code. Nếu cần nhãn do chính bạn gán: sửa data/seed_raw.tsv và cột human_label trong data/audit_sample.csv, rồi chạy lại build_dataset.py → run_experiments.py.
  • 85% nhãn đến từ gpt-4o, cùng họ với model D → có thể thiên vị D. Trên 37 tin test có nhãn người: D 0,973, A 0,905.
  • Tin nhắn sinh tổng hợp "sạch" hơn log thật; cần đánh giá lại trên dữ liệu production.
  • Latency đo từ một máy, ở một thời điểm; con số tuyệt đối thay đổi theo mạng và tải, chênh lệch tương đối đáng tin hơn.
